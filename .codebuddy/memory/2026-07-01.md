## prompt.go 复测 + 精简重写（5 轮迭代结论）
- 本地跑法固定：`go build -o /tmp/ss-test .` → `LOG_DIR=/tmp/ss-log PORT=8081 nohup /tmp/ss-test &` → `cd server/src/test && python3 test_api.py --local -v`（config.go 内置真 DeepSeek key）。日志 /tmp/ss-log/testN.log。
- 关键发现：**DeepSeek 对正例最敏感、对成堆 NEVER 反而困惑**。加口语拆解正例后「去海南」稳定拆成 `["海南","hainan"]`。
- **精简重写**：原 prompt 96 行，同一条"别塞整句"红线重复 5 处。重写为约 60 行（去重、正例优先、STEP1 filters / STEP2 content A/B/C / KEY 段 / WORDING 段结构）。精简约 40%。
- **踩坑**：精简时误删了"保留用户原词、不改颜色"约束，导致「穿红衣服的人」退化成 summary"穿灰色衣服的人"+gray_clothing 幻觉。→ 补回一条精炼 WORDING 红线（`keep exact words, 红≠灰 猫≠狗, summary/tags 不加料`）即根治。
- 最终 test_api.py --local 5/5 通过：filters（去年/上周/大于5M）、同义词、sensitiveTypes、red_clothing 全对。
- **残留顽疾（纯 prompt 根除不掉，3+轮验证）**：模型即使已用 filters/visualTags 表达，仍习惯性把整句也塞进 searchKeywordGroups（4/5，如"找大于5M的视频"整句）。整句做 substring 匹配几乎命中不了、跨组 AND 会误清空结果。→ 待办：服务端 normalizeSearchPlan(raw,query,config) 里兜底清洗——当 plan 已有 visual/sensitive/filters 非空时，剔除 searchKeywordGroups 中≈整句 query 的项（子串+rune 重合度≥0.7）。models.go 中 Filters 为值类型，入口在 handler.go 调 normalizeSearchPlan。
- **中文 prompt 实验（结论：不要用中文）**：把整份 prompt 翻成中文后 test_api.py --local 从 5/5 掉到 2/5，且几乎全空——filters {}、所有 must 数组 []、连 confidence 都丢。DeepSeek 在中文指令下明显"偷懒"不抽取，英文技术性指令执行更认真。已回滚英文版。→ prompt 保持英文（query/枚举/中文触发词内联即可）。
- **极简 prompt 实验（结论：不要过度精简）**：写了约 40 行正例驱动极简版，核心抽取仍 5/5（filters/visualTags/sensitiveTypes 全对），但 DeepSeek 输出变不稳：summary 偶发 UTF-8 双重编码乱码（Ã¦ÂÂ¾…）、confidence 偶发丢失（None）。乱码会直接展示给用户，不可接受。→ 保留完整英文版（72 行，已验证 5/5 且 summary/confidence 稳定）。省的 token 不值得牺牲稳定性。当前 prompt.go = 该完整英文版。

## 设计结论：不要把 query 翻成英文（会帮倒忙）
- searchKeywordGroups 的匹配 haystack = SmartSearch.swift:89 searchableDescriptionText = caption+localizedLabels+ocrSummary+placemark+albumNames，其中 placemark(地名)/albumNames(相册名)/ocrSummary(OCR) 在中文环境下基本是中文。SearchEngine.swift matchKeywordGroups 做 lowercased substring 命中（组内 OR、组间 AND）。
- 所以现在 prompt 要求同组中英并存（["海南","hainan"]）是刻意设计：两条命中路径都保留。若把 query 翻成英文，keyword 只剩英文 → 命中不了中文相册名/地名/OCR → 直接搜不到结果。
- 另外翻译层多一次 LLM 调用（延迟×2/成本×2/翻译误差），summary 还要给中文用户看。DeepSeek 中文 query 已 5/5，不是出错源。
- 结论：prompt 保持英文，query 保持中文原文，关键词组中英并存别动。整句复制顽疾只能靠服务端兜底清洗（剔除 ≈整句 keyword），翻译 query 解决不了。
