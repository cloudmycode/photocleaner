# 连续快速划选

日期：2026-10-31。

## 交互与安全边界

- 手势输入由照片区域统一接收，不再因当前照片、动画或保存状态变化而取消原有指针流。
- 新的一次 DOWN 提前结束上一张剩余的视觉动画，保留保存任务；已加载的下一张立即跟随手指。
- `SwipeInbox` 仅容纳一个新划动，包含照片 URI、内容签名、位移、是否完整抬手。禁止仅缓存方向并在之后套用到任意照片。
- 普通划动完成立即提交；过渡期间完成的下一划等前一张保存成功、对应照片成为当前照片并呈现后再提交。手指跨越换图时继续接收 MOVE/UP。
- 阈值与原来相同：超过 80dp 且垂直位移大于水平位移的 1.2 倍。短划、取消、双指缩放不提交。
- 保存失败清除下一划，恢复当前照片；退到后台清除尚未提交的暂存，不在恢复后偷偷执行。
- 未加载的照片不接受决定；磁盘异常缓慢导致暂存已满时明确提示等待，不无限排队操作未看见的照片。
- Remove 仍只标记待删，实际删除继续走原有确认流程。
- 划选页底部中间 Kept / Marked to remove 信息已移除。

## 验证

- Debug、独立设备测试包构建通过；51 项单元测试通过；Lint 0 errors（31 warnings）。
- API 36 模拟器：4 项新增连续划选场景、1 项现有缩放场景、3 项手势仲裁测试，共 8 项通过。
- 华为 BLA-AL00 / Android 8.1 / API 27：上述 4 项连续划选场景与双指缩放场景，共 5 项通过。
- 模拟器既有撤销、重建恢复、删除确认和照片详情回归通过。完成月份回归初次在“重置进度”后断言过早：原测试等待已在后台显示的首页标题，未等待异步写入结束；改为等待重新出现 Start sorting 后复测通过。合计 3 项相关回归最终通过。
- 新增场景验证：两个 80ms 相反方向划动发生于 230ms 飞出动画完成前；第二划按下在换图前、抬起在换图后；取消下一划；模拟 SQLite 保存失败后没有错误操作其他照片。断言具体照片对应的 KEEP/REMOVE 记录，测试照片未被实际删除。
- 设备测试使用独立 `.devicetest` 应用与白名单生成图片，不读取或重置普通版的整理记录。

这是交互正确性验证，不是帧率测试；没有据此宣称恒定 60fps 或在存储长时间阻塞时无限接收划动。
