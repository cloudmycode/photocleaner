# 删除过程的进度反馈

## 行为

- Android 8.1/9 的既有流程逐张核对照片、调用系统删除，再保存可恢复的结果；Android 10 复用相同队列并处理逐张授权。新增进度不改变删除安全策略。
- 处理中显示蓝色进度条、处理百分比、`12 of 40 processed` 和已确认释放的空间。失败项计入处理数，但不计入释放空间，并单独显示失败数量。
- 准备队列、等待系统授权时显示不定进度；写入最终照片列表时显示 `Updating library…`。Android 11+ 的系统批量删除没有中间逐张结果，不模拟百分比。
- 进度由已持久化结果产生，通过独立 StateFlow 仅刷新小面板，不重建照片网格或照片分组。进度条以 180 ms 动画跟随实际数值。

## 验证

- 58 项单元测试通过；新增测试覆盖进度与持久化结果一致、失败字节不计入释放空间、系统授权不提前增加进度、Android 10 授权重试不重复计数。
- API 36 模拟器：进度组件、实际删除/取消/返回月份等流程共 2 项设备测试通过，见 `emulator-tests.txt`。
- 华为 BLA-AL00 / API 27：进度组件及完整删除流程通过。`phone-progress.png` 是组件在真机渲染的示例状态截图，数字用于测试，并非用户真实图库删除结果。
- 华为 40 张生成图片的真实删除测试通过，验证处理进度覆盖 0～40、成功字节与结果一致，且系统中无剩余测试图片。仅删除流程用时 13,142 ms：核对 809 ms、系统删除调用 11,883 ms（约 90%）、持久化日志 341 ms；见 `phone-timing-test.txt` 与 `phone-timing.txt`。不包括生成图片时间，不能作为所有用户图库的固定耗时承诺。
- 耗时测试首次执行因测试方法返回值不符合 JUnit 要求而未启动；修正为 Unit 后单独重跑通过。生产删除代码未因该测试修正而改变。
