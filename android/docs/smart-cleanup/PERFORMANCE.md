# 大相册扫描优化（1.0.6）

2026-11-01。只更新统一 APK，按用户要求不安装真机。

## 实现

- `SmartPhotoAnalyzer` 只协调扫描：两个解码协程、64 张一批、单一缓存写入者；互斥锁隔离新旧扫描，避免取消后原生解码尚未返回时开启更多解码任务。
- `PhotoFingerprintDecoder` 只读取和计算特征：64KB 缓冲复用图片头与解码流；图片头过大时回退到重新打开。灰度改为原生数组，哈希十六进制转换去掉逐字节格式化开销。
- `FingerprintStore` 独立负责 SQLite，采用预编译语句与每批一次事务。每次扫描结束或取消都会关闭数据库；已提交批次可复用，取消最多丢弃当前未提交的 64 张计算。
- 保持原有指纹格式、数据库版本及最终识别规则。没有引入系统缩略图，因为缩略图的旋转、裁切和解码差异可能影响现有缓存及判断结果。
- 缓存先展示，增量只解码新增或内容签名变化的照片。按拍摄时间和尺寸优先解码连拍候选，但仍需原有视觉相似规则确认；不会只凭时间分类。
- 新结果按批检查，最多约每 750ms 发布一次分组；极慢的单批解码会延后发布。完成前禁用清理确认，维持现有删除流程。
- 照片扫描不再被纯视频变化触发重启，进度总数排除视频。保留本次访问中已处理的单照片组。

## 验证

JVM 回归覆盖 12,477 张合成照片的最终分组等价性、冷扫描事务批次数、全缓存扫描不解码也不写库、仅重算新增/修改项、权限移除和视频排除、两个任务并发上限、中断后继续、无法读取项重试、扫描中途发布分组。

12,477 张、全部可读取且未缓存时，事务数从 12,477 降为 195（减少约 98.4%）；这不是整库扫描耗时减少 98.4%。首次扫描仍须读取所有未缓存照片。

Android 仪器测试 `SmartScanPerformanceTest` 仅在隔离模拟器中处理应用私有生成图片和临时数据库：比较旧解码算法与新算法的 JPG、PNG、纯色、大图片头结果；比较 12,477 条单条事务与批量事务耗时。具体运行结果另行记录。

真机的端到端耗时尚未测量，模拟器数据库基准不能代表华为手机的一万多张真实图片扫描耗时。低纹理图片仍需读取原始文件做精确摘要，较大或损坏文件仍可能拖慢一个批次。

## 本轮实测结果

- 82 项 JVM 单元测试通过；普通 Debug 构建与 Lint 通过。
- 新建独立 Android 16 / API 36 x86_64 模拟器（端口 5556），两个设备测试通过，合计 88.958 秒；未使用现有模拟器或用户真机。
- 12,477 行写入：逐条事务 **84,699ms**，64 行一批 **3,231ms**，本次数据库写入约快 **26.2 倍**。两组排除建表耗时，均为相同结构、合成记录和默认 SQLite 配置；这是单次模拟器测试，不能当作整库扫描提速倍数。
- 真实生成的 JPG、PNG、纯色、大图片头 JPG 的新旧特征完全一致；损坏图片按预期跳过。
